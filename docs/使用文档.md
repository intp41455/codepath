# 使用文档

本文分两部分：**A · 给学习者（怎么用这个网站学）** 与 **B · 给贡献者 / 维护者（怎么跑、怎么测、怎么改）**。

---

## A · 给学习者

### A1. 从哪里开始

1. 打开网站，首页是「今日学习」。先看**每日代码挑战**（5–10 分钟，可领当日 XP），或点「继续我的课程」进入上次停下的位置。
2. 第一次来就从 **Python 基础 · 第 1 课「让电脑说一句你好」**开始。
3. 左侧导航固定这几块：
   - **学习工作台**：当前小节 + 右侧代码编辑区。
   - **学习路径**：17 条阶段卡片，可自由跳转。
   - **实战项目**：14 个综合项目。
   - **审核与测试**：把你的代码送去运行 / 断言 / 静态扫描。
   - **我的笔记 / 学习记录**：自动收集 + 进度统计。

### A2. 一个小节怎么学（核心闭环）

每个可执行小节固定四步，请**按顺序**做：

1. **看懂**：先读「先理解一个小知识」，能用自己的话说出 `example` 这段代码做了什么。
2. **写出**：右侧写代码。点「运行并检查」，让练习的真实断言判定。
   - 通过 → 本节记入完成（首次 +20 XP）。
   - 不通过 → 读「检查」给出的原因，改到通过。
3. **调试**：故意改一处（比如把 `return n` 改成 `return -n`），看到断言失败，理解为什么失败。
4. **迁移**：完成「再想一步 / 独立掌握检查」的四个自查项，并回答反思题。

> 关键原则：**看过答案 ≠ 掌握**。点「查看参考答案」前，先自己写一遍。

### A3. 练习会「真实运行」吗？会怎么判？

- **Python / SQL**：浏览器内用真实 Pyodide + SQLite 执行，SQL 每次运行重建练习数据库。判定靠 `expected`（结果比对）或断言。
- **JavaScript / TypeScript**：在不透明 iframe + Worker 里执行；TS 会先做 strict 类型检查，类型错误直接拒。判定靠你写的业务断言。
- **本机指导类（Java / Spring / Linux 等）**：网页**不**替你编译 / 部署。它给你步骤 + 知识检查 + 自查清单；完成状态由你如实勾选，知识题由网页判定。

判定逻辑的三条底线（课程反复强调）：
- **没有断言 = 不算通过**（只 `console.log` 不等于验证了正确性）；
- **注释 / 死代码里的断言不算数**；
- **业务写错但语法对，也会被拒**（例如 `add` 写成 `a-b`）。

### A4. 进度、XP 与备份

- 进度存在**当前浏览器**（`localStorage`，键 `codepath-learning-v1`）。换浏览器 / 清缓存会丢。
- **XP 规则**：每节首次完成 +20；每个**本地日期**的每日挑战通过一次 +40（重复不叠加）。XP 只是本机记录，不等于能力。
- **迁移 / 备份**：页面底部「备份学习进度」导出 JSON；在新设备「导入备份」合并。导入会校验格式与大小（>5MB 或结构不符会被拒），合并后 XP 按唯一记录计算，不会重复累加。
- **导出下载被浏览器拦截时**：导出对话会给出完整文本 + 「复制完整内容」回退，复制后本机另存即可。

### A5. 毕业验收（两套）

进入「实战项目」里的「毕业 A / 毕业 B」：

- **毕业 A · 接管自己的 AI 辅助项目**：逐句理解 → 端到端追流程 → 独立改行为 → 复现并修复故障 → 回归测试与干净环境交付。
- **毕业 B · 接手陌生 GitHub 仓库**：固定版本复现运行 → 解释模块职责与依赖 → 追调用链 → 完成小改动 + 回归 → 报告证据并标明局限。

每项有 5 个评分维度（0–3 分，满分 15），自评 `≥2 分/项` 且总分 `≥12`、每项证据 ≥20 字才算「记录完整」。页面可一键导出「毕业验收记录」。
> 再次强调：这检查的是**记录是否完整**，不是代码质量认证，仍需人工复核实际证据。

### A6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 点「运行」一直转圈 | 首次需联网下载运行环境，最长约 90 秒；仍失败检查网络后重试。 |
| 提示「执行超过 5 秒，已停止」 | 你写了无退出的循环，检查退出条件后重跑。 |
| 直接双击 HTML 打不开运行 | 用本地 HTTP 服务（见 B2），浏览器 Worker 需同源。 |
| 想让手机访问 | 网站是响应式，375px 宽度下首页 / 工作台 / 审核布局已适配。 |
| 想换设备继续学 | 旧设备导出 JSON 备份 → 新设备导入。 |

## B · 给贡献者 / 维护者

### B1. 仓库怎么跑

```bash
# 克隆
git clone https://github.com/intp41455/codepath.git
cd codepath

# 起本地静态服务（任选一种）
npm start                 # 等价于 node scripts/serve.cjs 4317
# 或
cd dist && python -m http.server 4317 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:4317
```

### B2. 怎么测（必须全绿再提交）

```bash
node --test tests/regression.cjs      # 60 项：课程断言 / 业务逻辑 / 静态规则
python tests/exercises.py             # 51 项 Python/SQL 参考实现 + 10 算法反例
python tests/runtime-python.py        # 51 参考 + 7 反例
python scripts/build-test-bundle.py   # 重新生成 dist/codepath-tests.zip
```

- Node 测试调用**真实**课程运行器 + 共享业务逻辑 + 规则扫描器，不是 mock。
- 负向用例（写错的业务 / 类型 / 死断言 / 输出洪水）必须被拒——改课程函数返回值时，对应测试应当失败。
- 浏览器 E2E 需另做：起服务 → 做题 / 重复领奖 / 刷新 / 备份导入 / JS·TS·Python 错误用例 / 无限循环停止 / 审核改码后结果失效 / 窄屏 / 键盘。Node 结构检查**不等于**浏览器隔离安全认证。

### B3. 怎么改课程 / 加小节

1. 找到对应课程文件（如 `dist/foundations.py` 在 `dist/*.js` 里以 `add({id, track, title, ...})` 形式追加；完整字段见 [架构](架构.md)）。
2. 可执行小节必须给出能区分「对 / 没写 / 业务错」的 `test` 或 `expected`；本机指导小节必须给 `checks`(≥2) 与 `quiz`。
3. 跑 `node --test tests/regression.cjs`，确认新增小节被数量 / 字段断言覆盖（当前断言 `lessons.length === 129`、`projects.length === 14`）。
4. 重新 `python scripts/build-test-bundle.py`，更新 `dist/codepath-tests.zip`。
5. 同步 `CHANGELOG.md` 与 README 的数量。

### B4. 怎么发布到站点

本仓库是**静态站点**，可直接托管：

- **GitHub Pages**：仓库已放 `dist/.nojekyll`，在 `Settings → Pages` 选 `main / dist` 分支即可；线上地址 `https://<user>.github.io/codepath/dist/`。
- 内部 ChatGPT Sites 发布为私有站点（仅所有者访问），发布与验证细节见内部《发布记录》文档。

### B5. 安全与合规

- **不要在代码 / 文档里写真实密钥**。示例占位符也注明「非真实」。
- 用户输入优先 `textContent`；富文本必须净化（见 `learning-core.js` 的 `html` 规则）。
- 静态规则是启发式，**改规则要同步补正 / 负向用例**。
- 随仓库分发的 TS 编译器保留其原始许可（`dist/vendor/typescript/LICENSE.txt`），改版本时一并更新该文件与测试里引用的库名。
